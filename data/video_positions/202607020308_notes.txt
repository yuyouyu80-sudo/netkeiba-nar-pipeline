■ オフセット確認
画面右上に小さく表示される経過秒数(スタートからの経過時間、例: "17" "1.27" 等)を複数フレームで実測。
- frame_0008 → 表示 "5"  → offset = 8-5 = 3
- frame_0013 → 表示 "10" → offset = 13-10 = 3
- frame_0018 → 表示 "15" → offset = 18-15 = 3
- frame_0020 → 表示 "17" → offset = 20-17 = 3
- frame_0023 → 表示 "20" → offset = 23-20 = 3
- frame_0025 → 表示 "22" → offset = 25-22 = 3
- frame_0028 → 表示 "25" → offset = 28-25 = 3
- frame_0060 → 表示 "57" → offset = 60-57 = 3
- frame_0090 → 表示 "1.27"(=87秒) → offset = 90-87 = 3
全て offset=3 で完全一致(タスク冒頭の想定値offset=4とは異なるが、本レースでは3で安定)。
以降 frame番号 = round(t + 3) で算出。

■ 読み取り方法の詳細
画面下部の色付き丸アイコン(枠番色、内側数字=馬番)の横位置を「左ほど先頭」として左から順に読み取った。
上下2段になっている場合は段を無視して横位置のみで順序付けした。
なお馬番「2」(黒丸)は、読み取れた全てのkick/dashフレームで一貫して他の集団から離れて左端(=先頭)に
単独で位置しており、他馬とは明確な間隔(ギャップ)を保っていた。逃げ・先行馬として単独先頭を保っていた
可能性が高いが、本馬体のゼッケンでの直接確認はできていない(アイコン列のみでの判断)。

■ 判読精度に関する注記(重要・正直な申告)
- 先頭(「2」の単独走行)や最後方など、他と明確な間隔があるアイコンは比較的高い確信度で読めた。
- 一方、中団の密集区間(概ね5〜9頭が横一列に近い状態で重なって表示される区間)は、アイコン同士の
  横位置差が数ピクセル〜十数ピクセル程度しかなく、厳密な着順の入れ替わりまでは判読しきれていない。
  中団内の細かい順位(隣接する1〜2位差)は誤差を含みうる前提でCSVを作成した。
  (confidence列は指示通り "medium(vision-read)" 固定としているが、実態としても中団は誤差が乗りやすい)
- 判読に全く自信が持てなかった馬番はその行を省略した(例: t=60〜75付近で馬番8・10が断続的に省略、
  t=90以降で馬番12・13が断続的に省略、など)。
- 全フレームを通じてスロー再生・リプレイの疑いは無かった。ただし frame_0066とframe_0069は
  経過時間表示が両方とも "1.02.9"(distance marker "1000m" 併記)で同一値だった。実時間では3秒差があるはずだが、
  これは「1000m通過タイム」のスプリットタイム表示がその間ホールドされている一般的な放送演出と判断し、
  実際に両フレームの馬の位置(ボケ足の位置)は異なっていたため、フリーズフレームや重複フレームではないと判断した。
  念のため異常ジャンプ候補としてここに記録しておく。
